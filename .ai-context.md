## Overview

This repository contains the documentation site for **Octez Connect** (formerly Beacon), built with **Docusaurus v3**.  
The codebase and docs have been migrated from the legacy `@airgap/*` (Beacon) namespace to the new `@tezos-x/octez.connect-*` namespace.

## Key Information

- **NPM Scope**: `@tezos-x`
- **Core SDK**: `@tezos-x/octez.connect-sdk`
- **Docs URL (production)**: `https://octez-connect.tezos.com` (configured in `docusaurus.config.js`)
- **Edit-on-GitHub base**: `https://github.com/trilitech/octez.connect-docs` (see `editUrl` in `docusaurus.config.js`)
- **Migration Guide**: `src/docs/guides/migration-from-beacon-sdk.mdx`
- **External References**:
  - NPM packages: `https://www.npmjs.com/settings/tezos-x/packages`
  - Repository owner: Trilitech

## Repository Structure (docs-related)

- `src/docs/`: MDX documentation content. All references to old packages have been updated.
- `src/examples/`: Runnable code examples used in the playground/live code blocks.  
  - Old `*.beacon.ts` / `*.taquito.ts` files have been renamed to `*.octez.connect.ts` and `*.octez.js.ts`.
- `scripts/`:
  - `fix-octez.connect-sdk.js`: post-install fix for the SDK layout (used by `npm prepare`).
  - `generate-monaco-types.js`, `copy-examples.js`: support code for embedding examples and Monaco types.
- `docs/` and `build-docs/`: Generated/processed docs folders used by the `embed-code` pipeline (see below).
- `package.json`: Docusaurus + SDK dependencies and all doc build scripts.

## Node & Tooling Requirements

- **Node**: `>=22` (enforced via the `engines` field in `package.json`).  
  - Use `nvm` and run `nvm use 22` (or higher) before working on the repo.
- **Package manager**: `npm` (scripts in `package.json` assume `npm`).

## Core NPM Scripts (how the docs are built)

From `package.json`:

- **Local development**: `npm start`
  - Runs:
    - `npm run create-node-modules`
    - `npm run embed-code`
    - `docusaurus start`
  - **Behavior**:
    - Copies `@tezos-x/octez.connect-sdk` into `src/node_modules` so examples can import from a stable local path.
    - Generates Monaco types and embeds code examples into the MDX docs.
    - Starts the Docusaurus dev server.

- **Prepare hook**: `npm prepare`
  - Runs `node scripts/fix-octez.connect-sdk.js`.
  - Ensures the SDK file layout under `node_modules/@tezos-x/octez.connect-sdk` matches what the docs & examples expect.

- **Production build**: `npm run build`
  - Runs:
    - `npm run create-node-modules`
    - `npm run embed-code`
    - `docusaurus build`
  - Output is placed in the standard Docusaurus `build/` directory.

- **Deployment (Docusaurus default)**: `npm run deploy`
  - Runs `docusaurus deploy`, configured with:
    - `url: "https://octez.connect.tezos.com"`
    - `baseUrl: "/"`  
    - `organizationName: "trilitech"`
    - `projectName: "octez.connect-docs"`
  - Intended for GitHub Pages-style flows, but can be adapted to CI/CD as needed.

### Embed / Examples Pipeline

The `embed-code` script is central to keeping examples and docs in sync:

- `npm run embed-code`:
  - Runs `npm run generate-monaco-types` to produce types for the playground/editor.
  - Runs `npm run prettier` / `npm run pretty-source` to normalize formatting.
  - Compiles example `.ts` files under `src/examples/` with `tsc`.
  - Runs `scripts/copy-examples.js` to copy compiled examples where the docs expect them.
  - Clears and recreates `build-docs/` and `docs/` via `remove-folders`/`clear-folders`.
  - Copies from `src/docs/` into `build-docs`, then moves that into `docs/` and prettifies the docs (`pretty-docs`).

**Important**: When editing examples or docs, always rely on the `start`/`build` scripts instead of invoking `docusaurus` directly, so that the embedding pipeline runs and generated files stay consistent.

## Local Development Workflow

1. Ensure Node 22+ is active (e.g. via `nvm use 22`).
2. Install dependencies: `npm install`.
3. Run the dev server: `npm start`.
4. Edit MDX docs under `src/docs/` and examples under `src/examples/`.
5. Use `npm run prettier` or `npm run pretty-docs` to keep formatting consistent when making larger structural/content changes.

## Build & Deployment Notes

- **Production build**:
  - Run `npm run build` to produce a static site in `build/`.
- **Deployment**:
  - The canonical production site is `https://octez.connect.tezos.com`.
  - For GitHub Pages-style deployments, `npm run deploy` uses the Docusaurus config (`organizationName`, `projectName`, `url`, `baseUrl`).
  - For non-GitHub deployments (e.g. internal infra), use `npm run build` and publish the `build/` directory using your platform of choice (e.g. S3 + CloudFront, Netlify, etc.).

## Maintenance Tips

- **Namespace consistency**:
  - All new references should use the `@tezos-x/*` packages (`@tezos-x/octez.connect-sdk`, `@tezos-x/octez.js`, etc.).
  - Legacy Beacon references should be updated or documented only within migration guides.

- **SDK version alignment**:
  - Keep the versions of `@tezos-x/*` dependencies in `package.json` aligned with the versions documented in the guides.
  - When bumping SDK versions, verify:
    - Examples under `src/examples/` still compile.
    - Docs under `src/docs/` reference the updated APIs and versions.

- **Broken links**:
  - `docusaurus.config.js` has `onBrokenLinks: "throw"`.  
  - Fix or update any broken links before merging changes; the build will fail otherwise.

- **Playground & Monaco**:
  - Any new example added to `src/examples/` that should appear in the playground must:
    - Compile via `tsc` under the options used in `embed-code`.
    - Integrate with Monaco types generated by `scripts/generate-monaco-types.js`.

- **Content formatting**:
  - Use `npm run prettier`, `npm run pretty-source`, and `npm run pretty-docs` to keep markdown, MDX, and TS examples consistently formatted.
  - This helps avoid noisy diffs and keeps the docs easy to maintain.
